How Scoring Works

From accepted evidence to subdimension maturity, dimension averages, and normalized scores.

This explanation describes the current implementation, including where it differs from the scoring documentation.

1. Scoring Subdimensions

Each subdimension gets a maturity level from 1 to 4, or null if there is insufficient evidence.

Maturity levels and their fixed normalized values
LevelMeaningRangeActual score
1Basic / Not Met25–4033
2Developing / Partially Met50–6558
3Established / Mostly Met70–8578
4Advanced / Fully Met90–10095

Only accepted evidence assigned to that specific subdimension is used. Proposed or rejected evidence does not count.

When an LLM is configured

The AI reads the evidence claims and recommends a maturity level, confidence, and rationale. There are no coded numerical thresholds such as “NRR above 110% means Level 3.” The level is an AI judgment against the rubric. Users can override a maturity level with a reason.

When the LLM is unavailable or fails

A mock heuristic uses evidence-quality signals:

  • Three or more accepted items, with at least one primary source and at least one resolved URL: Level 3, high confidence.
  • Otherwise, two or more accepted items with a primary source or resolved URL: Level 3, medium confidence.
  • Otherwise, at least one accepted item with a resolved URL: Level 2, medium confidence.
  • Otherwise, any accepted evidence: Level 2, low confidence.

A primary source here means an annual report or regulatory filing. The primary source and resolved URL do not have to belong to the same evidence item.

Fallback limitation: the heuristic only produces Levels 2 and 3. It measures evidence signals, not the organizational capability described by the evidence.

Implementation: scoring recommendation logic.

2. Averaging Into a Dimension

The system averages maturity levels, not normalized scores. All scored subdimensions have equal weight.

Dimension maturity = round(sum of non-null subdimension levels / number of non-null subdimension levels)

Example: Revenue Durability
SubdimensionMaturityNormalized score
Retention258
Pricing power378
Customer concentration378

The maturity average is (2 + 3 + 3) / 3 = 2.67, rounded to Level 3. The dimension normalized score is therefore 78.

It does not average 58, 78, and 78 to get 71.33. Rounding happens before the dimension is normalized; halfway values round up.

Implementation: maturity averaging and normalization.

3. Choosing a Value Within the Range

The system always takes the rounded midpoint. Evidence strength and confidence do not move the score within the range.

Normalized score = round((range minimum + range maximum) / 2)

For Level 1: (25 + 40) / 2 = 32.5, rounded to 33.

A “weak Level 1” and a “strong Level 1” both receive 33. This is a fixed representation of the maturity level, not continuous statistical normalization.

Documentation versus implementation: the documentation mentions manual within-range adjustment, but the current scoring APIs accept a maturity level and recalculate its midpoint. They do not implement choosing, for example, 28 versus 38.

References: scoring documentation, subdimension scoring API, and dimension scoring API.

4. Handling Missing Evidence

Missing evidence means unknown, not zero and not Level 1. A subdimension with no accepted evidence receives null maturity, null normalized score, low confidence, and an insufficient-evidence status.

The LLM can also return null when accepted evidence exists but is inadequate. Null maturity levels are excluded from the dimension average.

Confidence is separate from maturity

Dimension confidence is aggregated only from scored subdimensions. The code maps low to 1, medium to 2, and high to 3, then averages: an average of at least 2.5 is high; at least 1.5 is medium; otherwise it is low. No scored subdimensions means low confidence.

Implementation gap: the documentation says partial coverage should force low dimension confidence. The actual code does not enforce that rule. One high-confidence subdimension can produce a high-confidence dimension even when the other two are missing.

Confidence does not change the maturity or normalized score. Missing subdimensions are excluded without a numerical penalty.

Implementation: dimension calculation and confidence aggregation.

In short: accepted evidence → recommended maturity → equal-weight average of available levels → rounding → fixed range midpoint.
